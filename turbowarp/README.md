# 用 TurboWarp 编写 TurboMC 脚本

TurboWarp 是本项目**唯一**的脚本编辑方式。游戏内只负责加载与运行，不提供积木拼接
（可以查看脚本树，但不能改）。

## 一、加载扩展

1. 打开 <https://turbowarp.org/editor>
2. 左下角「添加扩展」（积木面板底部的 ＋）
3. 滚到底部选「Custom Extension / 自定义扩展」
4. 选 **File** 标签，加载 `turbomc-extension.js`
   - 装了模组的话，游戏启动后会自动释放一份到 `.minecraft/config/turbomc/turbomc-extension.js`，
     直接用那个即可，不用再从仓库找
   - 仓库里 `turbowarp/turbomc-extension.js` 是同一份源文件；两者内容不一致时说明模组版本旧了
5. 积木面板出现紫色的 **TurboMC** 分类

> 也可以用 **Text** 标签把 js 内容粘贴进去，效果相同。
>
> `config/turbomc/` 下那份是模组每次启动按 jar 内版本覆盖的，改扩展请改仓库里的源文件。

## 二、扩展积木清单

积木面板按下面 11 个分组排列，编辑器里每组前有一条加粗标题（`LABEL`）：
事件 / 移动与视角 / 输入 / 挖掘 / 容器 / 玩家状态 / 世界查询 / 实体查询 / 显示与日志 / 聊天与 AI / JSON。
标题只是面板里的分隔文字，不是积木、不会写进 `.sb3`；下一节的「攻击」是说明，不是分组。

### 事件

| 积木 | 说明 |
|---|---|
| 当受伤时 | 血量下降时触发 |
| 当玩家死亡 | 死亡边沿触发一次 |
| 当聊天包含 [MATCH] | 收到含关键词的聊天时触发；留空表示不过滤 |

### 移动与视角

| 积木 | 说明 |
|---|---|
| 走向 x:[X] y:[Y] z:[Z] | 用原版僵尸的 A\* 寻路走到目标坐标，遇到障碍会绕行。三个参数都是方块坐标，y 是目标**站立格**的高度。一次算不到目标时会先走近再接着算；总计约 60 秒走不到才放弃并松手。目标在水下时会下潜过去，氧气不足则中止并自动浮出水面 |
| 设置视角 水平:[YAW] 俯仰:[PITCH] | 直接设定视角角度 |
| 看向 x:[X] y:[Y] z:[Z] | 视角看向世界坐标（瞬时） |
| 平滑转到视角 水平:[YAW] 俯仰:[PITCH] | 用约 0.3 秒转到指定角度，**阻塞**到转到位。转头速度按剩余角度收敛，不是匀速 |
| 平滑看向 x:[X] y:[Y] z:[Z] | 同上，先算出目标方向再转。目标与眼睛重合时忽略 |
| 停止移动 | 释放所有移动键（同时也中止「走向 / 平滑转向」） |

### 输入

| 积木 | 说明 |
|---|---|
| 按键 [KEY] [按下/松开] | 按住或释放某个键。KEY 是下拉菜单，内置 Minecraft 全部 123 个键名（字母、数字、F1–F25、方向、修饰键、标点、鼠标三键、小键盘、功能键），直接选即可；要拼动态键名可拖入表达式 |
| 点击 [左/右/中] | 单次点击 |
| 按下鼠标 [左/右/中]? | 判断某个鼠标键是否**正被按住**（布尔）。读物理鼠标状态，打开背包/聊天界面时同样有效 |
| 点按 [KEY] 按住 [HOLD] tick | 按下并按住指定 tick 数后松开（阻塞）。KEY 同样是内置键名菜单 |

### 攻击：用左键点击，不提供专用积木

没有「攻击最近实体」这类积木，攻击靠输入积木完成：

```
点击 [左键]              ← 打准星指着的目标，走原版的射线与距离判定
按住 [mouse.left] 为「开」 ← 持续按住，由游戏自己按冷却出刀
```

**为什么不做攻击积木**：自己算「最近的实体」再发攻击包，很容易选到掉落物、经验球、
插在地上的箭——这几类在服务端会被判为「无效实体」并**直接断开连接**
（`multiplayer.disconnect.invalid_entity_attacked`），不是忽略。而且这类自动攻击
在带反作弊的服务器上还有转向突变、等间隔连点这些特征。

走左键点击则是原版管线：客户端自己做射线检测、自己判断目标与距离，服务端看到的
和玩家手点完全一样。

### 挖掘

| 积木 | 说明 |
|---|---|
| 等待方块被挖破 | 阻塞直到准星方块消失（上限约 10 秒） |
| 正在挖掘 | 是否处于挖掘状态 |
| 挖掘进度 | 当前方块破坏进度 |

### 容器

| 积木 | 说明 |
|---|---|
| 打开坐标处的容器 x/y/z | 精确指定；超过 5 格会被服务端拒绝 |
| 界面槽位数 | 没有界面时返回 0——可用来判断「到底打开了没有」 |
| 槽位 [i] 的物品 | 返回注册名如 `minecraft:iron_ore`；空槽返回空串 |
| 槽位 [i] 的数量 | 空槽返回 0 |
| 第一个装着 [物品] 的槽位 | 找不到返回 -1；比脚本自己循环 36 格可靠 |
| 点击槽位 [i] 用 [左/右] | 拿起或放下；需要界面已经打开 |
| 快速移动槽位 [i] | 相当于 Shift+点击，容器与背包之间自动转移 |
| 关闭界面 | 恢复移动与操作 |

> 容器的槽位编号是固定的。以熔炉为例：`0` 输入、`1` 燃料、`2` 输出，
> 之后 27 格是玩家背包，最后 9 格是快捷栏。
>
> **点击是异步的**：发包后要等服务端回发槽位更新，同一帧内读到的仍是旧值。
> 每次点击后至少等 1 tick 再读状态，否则会写出「以为没动、重复搬十次」的脚本。
>
> 自动熔炼的一个可用写法：
>
> ```
> 打开坐标处的容器 (熔炉 x y z)
> 等待 0.3 秒                      ← 等界面真的打开
> 设 ore = 第一个装着 minecraft:iron_ore 的槽位
> 如果 非 (ore < 0) 则        ← 没有 ≥ 积木，用「非 (小于)」
>     快速移动槽位 (ore)           ← 直接进输入槽
> 设 coal = 第一个装着 minecraft:coal 的槽位
> 如果 非 (coal < 0) 则
>     快速移动槽位 (coal)
> 等待 10 秒                       ← 等烧炼
> 快速移动槽位 (2)                 ← 取出产物
> 关闭界面
> ```

### 玩家状态

血量、饱食度、X/Y/Z 坐标、当前槽位、经验等级、手持物品、手持耐久百分比、背包已满?、
背包中 [ITEM] 的数量、重生

### 世界查询

是白天?、当前维度、在水中?、在岩浆中?、当前生物群系、脚下方块、坐标处方块、准星所指方块、
准星方块 X / Y / Z、服务端延迟 (ms)

> 「准星方块 X/Y/Z」给的是**准星指向的那一格坐标**：瞄到方块就是该方块，朝天空看（射线没命中任何
> 碰撞箱）时取「视线尽头」那一格——空气格也是合法坐标，所以永远有值，不会退化成 0,0,0。
> 要判断「是否真的瞄到了方块」，用「前方有方块？」。

### 实体查询

最近 [TYPE] 距离 / X / Y / Z、最近 [TYPE] 名称、附近 [TYPE] 数量

> `[TYPE]` 在编辑器里是**下拉菜单**，不用记 id：任意实体 / 敌对生物 / 玩家 + 本版本全部 157 个实体
> （下拉框支持输入搜索，敲「僵尸」「船」即可定位）。想填菜单外的生物（其他整合包的模组实体）时，
> 把下拉换成 `文本` 积木写实体 id 即可，也接受省略命名空间的写法（`zombie` = `minecraft:zombie`）；
> 大小写与首尾空格不敏感。老工程里的这几块积木没有这个参数，等价于 `any`。物品参数（`[ITEM]`）同款，
> 下拉里是本版本全部 1505 个物品。

### 显示与日志

| 积木 | 说明 |
|---|---|
| 从 x1 y1 z1 到 x2 y2 z2 画框 颜色 `[COLOR]` | 在世界里画出这两个角点围成的长方体线框。两端方块**都包含**在内；同屏最多保留 128 个框，超出时挤掉最早画的。反复画同一个框不会重复占位 |
| 清除所有画框 | 立刻清空全部框 |
| 输出日志 [TEXT] | 写一行到游戏日志（`logs/latest.log`），调试用 |

> 坐标完全由脚本自己算，积木不保存"选区"：想框住玩家的 10×10 范围，就用
> `玩家 X − 5` 这类运算积木拼出来。要标出多个目标，放进 `重复` / `遍历` 里连续画即可，
> 每个框可以自带颜色。停止脚本引擎、切换工程、退出世界都会自动清空。

### 聊天与 AI

| 积木 | 说明 |
|---|---|
| 最近的聊天 | 最近一条通过去重的聊天原文；从没收到过则为空串 |
| 让会话 [SESSION] 回应 [TEXT] | 把 `[TEXT]` 发给模型并**等待回复**，等待期间脚本挂起 |
| 会话 [SESSION] 的最后回复 | 取回该会话最近一次成功回复；失败或未完成是空串 |
| 清空会话 [SESSION] 的对话记录 | 清历史，保留系统提示 |
| 设置会话 [SESSION] 的系统提示为 [TEXT] | 改人格，**同时清空历史**（人格换了，旧对话留着只会让模型前后矛盾） |

### JSON

从 TurboWarp 扩展库的 `Skyhigh173/json`（MIT，Skyhigh173 & Mio）移植，语义逐条对齐。
**所有输入输出都是 JSON 文本**：积木不修改原值，而是返回一串新的 JSON，所以写法是
`设 v = (set ... in (v) to ...)`，链式套用。

面板里按五个子分组排列，标题形如 `JSON · 校验与新建`，只是分隔线、不是积木：

| 分组 | 积木 |
|---|---|
| `JSON · 校验与新建` | `[json] 是 [合法 JSON/对象/数组] 吗?`、`新建 [对象/数组]`、`[json] 的长度`、`[json] 包含键 [key] 吗?`、`[json] 的全部 [键/值/键值对]`、`[json] 的解析错误`、`压缩 [json]` |
| `JSON · 对象与路径` | `[json] 中 [item] 的值`、`把 [json] 中 [item] 设为 [value]`、`删除 [json] 中的 [item]`、`[json] 中路径 [path] 的值`、`把 [json] 中路径 [path] 的值设为 [data]` |
| `JSON · 数组读写` | `向数组 [json] 添加 [item]`、`把数组 [json] 的第 [pos] 项换成 [item]`、`在数组 [json] 的第 [pos] 项插入 [item]`、`删除数组 [json] 的第 [item] 项`、`删除数组 [json] 中所有 [item]`、`[item] 在数组 [json] 中的项号`、`数组 [json] 的第 [item] 到第 [item2] 项`、`把数组 [json] 的长度设为 [len]` |
| `JSON · 数组变换` | `拼接数组 [json] 和 [json2]`、`数组 [json] 中所有对象的 [key] 值`、`按分隔符 [d] 把文本 [text] 拆成数组`、`用分隔符 [d] 把数组 [json] 拼成文本`、`数组 [list] 按 [order] 排序`、`筛选数组 [list]…`、`数组 [list] 的 [analysis]` |
| `JSON · 与列表互通` | `把列表 [list] 读成数组`、`把列表 [list] 设为 [json]` |

> **索引统一为 1 基**：凡是对数组按位置操作的积木（含「`[json] 中 [item] 的值`」传数字时）都是
> `1` 第一项、`-1` 最后一项，`0` 与越界返回空串。早期版本里「按键取值」对数组用的是 0 基，
> 与其余积木不一致，已统一——旧脚本若依赖 0 基需要改。
> 路径积木的 `[path]` 是 **JSON 数组文本**（`["key","inner",1]`），不是点号表达式；
> 设路径只替换已存在的位置，中间层缺键直接返回空串（新建键请用「设为」）。
>
> **「抽字段」原文叫 filter，实际是从每个对象里取同一字段**；真正按文本筛的是「文本筛选」。
>
> **列表名是普通文本**，直接写列表名（不是下拉）。项目里列表按名字对应，
> 存 id 会在改名或复制工程后失效。
>
> 与原文的三处差异：解析错误返回中文说明带位置（浏览器文案无法跨引擎复刻）、
> 「长度」解析失败返回空串（原文是一个空格，显然是笔误）、嵌套深度上限 256
> （防御 Java 递归栈）。

`[SESSION]` 是普通文本，自己起名字（默认 `main`），用来隔离不同对话；同一个会话同时只允许一个在途请求。

**典型用法**：

```
当聊天包含 @ai
  让会话 main 回应 (最近的聊天)
  说 (会话 main 的最后回复)
```

`最近的聊天` 返回的是**完整消息**：带 `<玩家名> ` 前缀，也含关键词本身——上面那个例子里
它拿到的是 `<Player260> @ai 你是谁`。

- 这正好能区分是谁在说话（多人服尤其有用）
- 但**不能用「开头是 @ai」判断**，要用「包含 @ai」，否则永远不成立
- 想去掉前缀，用「在 … 中第一个 … 的位置」定位 `> ` 再截取

接口与密钥在 `config/turbomc.json` 的 `ai` 段（也可在 Mod Menu → TurboMC 设置 → AI 对话 里填）。
走 OpenAI 兼容协议，DeepSeek / 通义 / Kimi / 智谱 / Ollama / LM Studio 都适用。

```json
{
  "ai": {
    "baseUrl": "https://api.deepseek.com/v1",
    "apiKey": "",
    "model": "deepseek-chat",
    "temperature": 0.7,
    "maxTokens": 300,
    "timeoutMs": 30000,
    "historyTurns": 8,
    "maxConcurrent": 2
  }
}
```

| 字段 | 说明 |
|---|---|
| `baseUrl` | 不含 `/chat/completions`，宿主自己拼。空则积木直接失败 |
| `apiKey` | 明文存放；本地 Ollama 之类不需要时可留空 |
| `model` | 与 `baseUrl` 同时填了才生效 |
| `temperature` | 0–2，越低越稳定 |
| `maxTokens` | **发给模型**的长度上限（token），不是本地截断。模型会因此在句子中间停下 |
| `timeoutMs` | HTTP 超时；脚本侧等待上限自动比它多 2 秒 |
| `historyTurns` | 带多少轮历史（一问一答算一轮）。0 = 不带历史 |
| `maxConcurrent` | 全局并发上限，超出的请求立刻失败而不是排队 |

> **密钥是明文保存的**，`turbomc.json` 不要分发。密钥不进 sb3，工程文件可以随便分享。
>
> **HUD 气泡只有一行**，回复过长会被截断。把 `maxTokens` 压到 300 左右，并在系统提示里
> 要求「回答不超过 50 字」。
>
> **发到聊天栏前会自动清洗**：换行折成空格、`§` 及其格式码删掉。单条上限是
> **256 字符 / 768 字节**（服务端两个都校验，emoji 按 4 字节算，
> 纯 emoji 最多约 192 个）。模型回复经常带换行，原样发出去会被服务端判
> 「非法聊天字符」并直接踢出存档。
>
> **超长会自动分段**：长回复按标点切成多段，默认每 3 tick（约 150 毫秒）发一段，
> 最多 8 段（约 2000 字），超出部分末尾补 `…`。间隔与段数在模组设置 → 脚本引擎里调。
> 间隔别设成 1——原版服务端每秒上限 20 条，每 tick 一条会被判定刷屏。

## 三、可用的原生积木

**事件**：当绿旗被点击、当按下某键、当收到广播、当[计时器] > [N]
**控制**：如果、如果否则、重复、当…重复执行、对于…重复、永久循环、重复直到、等待、等待直到、停止
**侦测**：按下 [键]?、鼠标按下?（不分按钮，任一鼠标键按下即为真）、询问[问题]并等待、回答、用户名、计时器与当前时间
**运算**：比较、四则、取余、与或非、随机数、取整、拼接
**变量**：设定、读取、增加、显示/隐藏变量
**列表**：添加、删除、插入、替换、清空、取项、长度、包含、显示/隐藏列表
**外观**：说、思考（显示在 HUD 上）及其「N 秒」版本

> 需要「大于等于」时用 `非 (A < B)`。Scratch 原生没有 `≥` 积木，这里不再重复实现一个——
> 判等、大于、小于都有原生积木，组合即可，多一个近义积木只会让人犹豫该用哪个。

> 「询问并等待」会弹出输入窗口：确定提交内容，ESC 或取消视为空回答——两者都会让脚本继续，
> 不会把脚本卡死。角色可见时问题同时显示在 HUD 气泡上。
>
> 「显示/隐藏 变量、列表」把监视器画在 HUD 的状态框里，跟随「HUD 位置」设置；
> 列表最多显示几项可在模组设置里调（默认 5）。
>
> 「当[计时器] > [N]」的「响度」选项在游戏内没有音源，恒不成立；请用「计时器」。

## 四、不支持的积木

- **运动 / 造型 / 背景 / 声音 / 画笔**：Scratch 是 480×360 的 2D 舞台，模组是 3D 世界
  且服务器权威，强行映射会得到「看着像、落点全错」的行为。
- **克隆**：语义与 Minecraft 不对应，并发请用多个帽子积木。

自定义积木（`定义 xxx`）**可以导入并查看**，但游戏内不能修改。

## 五、导出与导入

1. TurboWarp 菜单 **File → Save to your computer**，得到 `.sb3`
2. 把 `.sb3` 放进 `config/turbomc/imports/`（游戏内 F7 → 「文件夹」可直接打开该目录）
3. 游戏内按 **F7** → 点「导入/更新」
4. 导入的包会自动成为「当前启用」；只有一个包能处于启用状态
5. 点圆点可切换启用，点「展开」可看到包内的每个脚本，「收起」恢复
6. 按 **F6** 启停引擎

导入时按「帽子积木」拆分脚本，命名为 `角色名` 或 `角色名-N`。同一角色下的多个脚本
共享该角色的局部变量，这与 Scratch 的语义一致。

## 六、注意事项

- **浏览器里看不到效果**：扩展积木在 TurboWarp 里只是空实现，真正的验证要在游戏里跑。
- **不要直接改 `turbomc-extension.js`**：它和游戏内那份 `es5` 都是生成的产物，源在
  `turbowarp/src/blocks.data.js`（积木、菜单）与 `items.data.js`（物品表）。
  改完运行 `node tools/build-extension.js` 重新生成，否则下次生成会覆盖你的修改；
  CI 会用 `--check` 拦下过期产物。
- **模组升级后要重新加载扩展**：TurboWarp 不会热更新已加载的扩展。顺序是
  「积木面板里移除 TurboMC → 添加扩展 → Custom Extension → File → 选 `turbomc-extension.js`」。
  `config/turbomc/` 下那份会在每次启动时按 jar 内版本覆盖，用它最不容易拿错版本；
  已保存的旧工程里可能内嵌着旧定义，验证新积木建议新开一个工程。
- **不要改扩展积木的 opcode**：模组按 `turbomc_<opcode>` 做映射，改名会导致积木失效。
- **变量名、列表名**按名称对应，中文可用。
- **扩展必须先加载再拼积木**，否则导出的项目里没有扩展积木。
- **导入的工程是只读的**：要改脚本请回 TurboWarp 改完重新导出、重新导入。
