# GUI 按钮功能审计

- **日期**：2026-11-05
- **触发**：用户反馈「点击导入，脚本列表里没有出现」
- **范围**：6 个界面、31 个可交互控件

---

## 1. 用户报告的问题

### 根因

方案 A 改掉了「导入」的语义，但 UI 没有跟着改：

```java
// ScriptStore.importSb3
Files.copy(path, dir.resolve("project.sb3"), REPLACE_EXISTING);
ScriptEngine.get().restart();          // 直接交给 VM 运行
return 1;                              // 不再生成 ScriptDefinition
```

旧版本会把 sb3 解析成一堆 `ScriptDefinition` 加进列表；现在的实现只是把文件复制成 `hkscript-vm/project.sb3` 并让引擎重启。**列表自然没有新条目**，只在底部有一行 3 秒就可能被盖住的绿字提示。

这是设计变更没有落到 UI 上，不是复制失败。

### 修复

1. **工程在列表里可见**：`ScriptStore.importedProject()` 读取 `hkscript-vm/project.sb3`，列表顶部固定显示一行
   `▣ 作品.sb3 (工程 · 运行中)`，右侧带删除按钮；
2. **删除即回退**：确认后删除工程文件并重启，引擎回到运行编辑器脚本；
3. **说明为什么编辑器没反应**：工程行下方加一行灰字「编辑器脚本暂停运行；删除该工程后恢复」。

之前最容易误解的一点——导入后去点脚本的开关、或进编辑器改积木都不生效——现在有明确文案。

---

## 2. 顺带发现：导出按钮导的是私有格式

`ScriptEditScreen` 的「导出」原本把 `ScriptDefinition` 序列化成自家 json（`GSON.toJson(definition)`）。这种文件只有本模组能读，**与 Scratch 生态完全不通**——用户拿它去 TurboWarp 打不开。

已改为导出 **sb3 工程**：

```
ProjectWriter.write(List.of(definition))
  → project.json + 一个空造型
  → zip 打包为 <脚本名>.sb3
  → config/hk-script/exports/
```

导出的文件可以直接在 TurboWarp 打开（需先加载 `turbowarp/hkscript-extension.js`，否则扩展积木显示为缺失）。

## 4. 仍然存在的行为差异

| 项 | 说明 |
|---|---|
| 工程运行时，编辑器的一切改动都不生效 | 已有文案，但用户仍需先删工程才能调试编辑器脚本 |
| 运行积木高亮 | 恒不显示（VM 不提供积木级定位） |
| 运行时面板 | 无实例/pc，只有线程数与变量快照 |
| 导入的工程不能在编辑器里改 | 方案 A 的既定取舍；要改用 TurboWarp |

---

## 5. 建议的复测步骤

1. 打开脚本列表 → 应看到 `▣ 作品.sb3 (工程 · 运行中)` 与下方灰字提示；
2. 点该行右侧「删除」→ 确认 → 提示消失，编辑器脚本恢复运行；
3. 再点「导入」→ 工程行重新出现，底部提示「已导入工程 …」；
4. 进任意编辑器脚本 → 点「导出」→ 检查 `config/hk-script/exports/<名字>.sb3` 是否存在、能否在 TurboWarp 打开；
5. 编辑任意积木参数 → 关闭编辑器 → 日志应出现一次「工程已启动」。
