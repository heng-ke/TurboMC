# 容器交互设计说明

脚本通过界面操作容器：打开、点槽位、搬东西、读槽位内容、关闭。
这组能力支撑自动熔炼、分类存储、按图案合成这类玩法。

## 一、积木与对应实现

| 积木 | 内部类型 | 说明 |
|---|---|---|
| 打开坐标处的容器 x/y/z | `action.open_container_at` | 精确指定；超过 5 格服务端会静默拒绝，因此提前告警 |
| 界面槽位数 | `world.container_slots` | 没有界面时为 0，可用于判断「到底打开了没有」 |
| 槽位 [i] 的物品 | `world.slot_item` | 返回注册名 `minecraft:iron_ore`；空槽返回空串 |
| 槽位 [i] 的数量 | `world.slot_amount` | 空槽返回 0 |
| 第一个装着 [物品] 的槽位 | `world.first_slot_of` | 找不到返回 -1 |
| 点击槽位 [i] 用 [左/右] | `action.click_slot` | `PICKUP`，拿起或放下 |
| 快速移动槽位 [i] | `action.quick_move_slot` | `QUICK_MOVE`，等价 Shift+点击 |
| 关闭界面 | `action.close_container` | 恢复移动与操作 |

实现都在 `action/ContainerActions.java`。返回**注册名**而不是显示名：显示名随语言变化，
脚本里的判断会跟着坏掉。

## 二、槽位编号是固定的

每个容器类型由 `ScreenHandler` 定义槽位顺序。熔炉为例：

```
0 = 输入     1 = 燃料     2 = 输出
3..29 = 玩家背包（27 格）      30..38 = 快捷栏（9 格）
```

所以搬运逻辑可以按容器类型查表，不必猜。`第一个装着 X 的槽位` 扫的是全部槽位
（容器格 + 背包），如果只想在背包里找，需要自己判断索引范围。

## 三、为什么只能走 `clickSlot`

`client.world` 只是服务端状态的副本。直接 `getBlockEntity(pos).setStack(...)` 看起来
「写成功了」，实际下一次同步就被覆盖——这是最容易被误认为可行的一条路。

`clickSlot` 发的是 `ClickSlotC2SPacket`，服务端校验后执行并回发槽位更新。它和玩家
手动点击走的是同一条链路，不是绕过校验。

```java
public void clickSlot(int syncId, int slotId, int button,
                      SlotActionType actionType, PlayerEntity player);
```

`SlotActionType` 七种，目前只用了前两个：

```
PICKUP       拿起 / 放下（button 0=左键，1=右键）
QUICK_MOVE   Shift+点击，容器与背包之间自动转移
SWAP         与快捷栏第 button 格交换
CLONE        仅创造模式
THROW        丢弃
QUICK_CRAFT  拖拽分堆
PICKUP_ALL   双击收集同类
```

## 四、必须知道的时序

**点击是异步的。** 发包 → 服务端处理 → 回发槽位更新，同一帧读到的仍是旧值。
每次点击后至少等一 tick 再读状态，否则会写出「以为物品没动、重复搬十次」的脚本。

**打开也不是即时的。** `interactBlock` 发包到界面真正出现有延迟，紧接着点槽位时
`界面槽位数` 可能还是 0。脚本里先「等待 0.3 秒」比较稳。

**高频点击会被节流。** `ScreenHandler` 有 revision 校验，连点同一槽位会触发客户端的
pending 队列保护。每 tick 一次通常没问题，但不要在一个循环里连点。

## 五、风险

**界面会挡住玩家。** 打开期间玩家看不到世界、无法移动，脚本必须自己负责关闭。
中途出错没关，玩家会卡在界面里——所以「关闭界面」应当写在脚本的收尾位置，
必要时配合超时判断。

**多人服务器可能不允许自动化。** `clickSlot` 在协议层完全合法，但服务器规则可能
禁止脚本操作。这是使用者的责任，代码不做限制。

## 六、明确不做的两件事

**不提供「直接设置容器内容」的积木。** 那必须绕开服务端，在多人服务器里等于内置作弊，
而且服务端版本一变就静默失效。

**不做容器抽象层**（比如「往任意容器放 X」）。各容器槽位规则差异大（熔炉 0/1/2、
合成台 0-9 图案），抽象会掩盖真实行为，脚本作者反而更难排查。
